# 验证范围

## 版本与时间

当前公开版本为 `v0.1.0-alpha.1`。记录日期为 2026-11-11。

Windows 本机运行了队列、配置安装器、真实 stdio MCP 与 JavaScript 通知回归。DSH 宿主使用 `0.2.2-rc.1`，通知恢复针对其当前会话组合服务验证。CodeArts 桌面原型使用 `0.2.8`，官方连接器卡片曾显示“已连接”。

## 已覆盖的检查

| 层次 | 检查内容 | 范围 |
| --- | --- | --- |
| 队列单元测试 | 提交去重、单执行归属、领取重试、令牌和路径校验、父端验收、退回、过期处理、取消竞态 | 临时 SQLite 与测试项目 |
| 配置安装器 | 幂等接入、其他条目内容保留、卸载、并发修改检测、中途写入回滚 | 临时 DSH/CodeArts 用户目录 |
| stdio MCP | 两角色工具清单、提交、领取、进度、模拟文件交付、查询与独立验收记录 | 真实 Python MCP 子进程，测试脚本模拟执行器 |
| 通知逻辑 | 原会话绑定、重复通知抑制、多实例竞争、重启恢复、修订再次通知 | 临时状态库与模拟会话接口 |
| DSH 宿主集成 | 公开源码的实际工具事件、插件加载、原会话通知、持久会话组合恢复 | 本机 DSH 独立验证主机，followup 在模型调用前截获 |
| 桌面配置 | 官方连接器配置与卡片显示 | Windows 本机原型观察 |

Python 测试当前包括 17 项，JavaScript 测试当前包括 7 项。安装器、协议、文档链接和样例均使用便携公开源码测试。公开源码还在本机 DSH 宿主中验证了工具事件、通知和原生会话恢复，验证过程截获后续模型消息。

2026-11-11，GitHub 的 Windows 与 Linux 工作节点均通过固定依赖安装及上述自动化测试。它们验证队列、配置、stdio 协议与通知逻辑，桌面客户端集成的操作系统范围仍按上表记录。[GitHub Checks](https://github.com/hsajdh/dsh-codearts-task-queue/actions/workflows/checks.yml)

## 待真实环境验证

- 用户在 CodeArts 桌面手动领取正式任务。
- CodeArts 模型使用原生工具修改对应项目，完成真实测试并回报交付。
- DSH 模型收到交付通知，实际读取文件、运行必要测试并给出验收结论。
- 不同 DSH/CodeArts 版本、其他操作系统、自定义安装及长期运行行为。

真实 CodeArts 桌面完整执行测试由开发者暂缓，初始桌面验收任务已取消。公开仓库的测试使用临时数据。首版以实验版发布，首次实际使用应从范围明确的小任务开始。

## 自己复查

```powershell
.\.venv\Scripts\python.exe scripts/configure.py --doctor --profiles desktop
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
node --test tests/test_review_relay.mjs
```

静态检查核对本机配置与已有数据库完整性。自动化测试运行临时 MCP 进程与模拟交付，使用自身的测试文件。桌面完整执行应按 README 的小任务示例单独进行，并记录执行版本、交付文件、实际命令与 DSH 独立验收证据。
