# 官方原生定时自动领取

CodeArts 桌面原生定时任务负责启动模型轮次，本地 MCP 负责领取与交付，原 DSH 会话负责独立验收。项目安装后可以继续使用手动入口，也可以按以下步骤创建原生计划。

## 创建前

先完成安装文档的两端接入，确认 CodeArts 的 dsh-task-queue 显示已连接，DSH 能提交一个具体的小任务。两个客户端使用相同的本机队列数据库，CodeArts 中打开对应工作区。[安装与本地接入](installation.md)

## 原生计划设置

1. 在 CodeArts 桌面左侧打开“定时任务”，选择“手动创建”。
2. 设置易于识别的名称，例如“DSH自动领取 · 当前项目”。
3. 工作空间选择对应的现有工作区。创建成功后该字段固定。
4. 将下方提示词中的 C:/projects/demo 替换为工作区的真实绝对路径，并填入“让码道做什么”。
5. 选择具有可用额度的模型。首次可沿用客户端默认模型。
6. 选择 Cron 表达式。示例 `*/30 9-23 * * *` 表示每天当地时间 09:00 至 23:30，每半小时执行一次。根据实际开发时段调整。
7. 创建后计划默认启用，在任务列表核对名称、工作区和执行频率。

官方还支持每天、每周和时间间隔。文档约束为同一工作区最多同时启用 3 项，执行日期区间最多 7 天，包含起始日。有效期与后续续设以客户端实际显示及平台规则为准。[官方定时任务文档](https://support.huaweicloud.com/usermanual-codeartsdesktop/desktop_0016.html)

```text
用户已授权本计划自动处理DSH派发到当前工作区的任务。
使用已安装的dsh-task-queue连接器调用claim_next，project_dir固定C:/projects/demo。
每轮生成新的唯一claim_key，同一轮重试沿用原key。
每轮最多处理一个任务，返回task为空或busy时结束本轮。
取得任务后先report_progress，再按task.instructions和task.acceptance执行。
操作范围为task.project及其子目录，使用CodeArts原生文件与终端权限。
完成后report_delivery提交真实文件路径、测试命令和结果。
受阻时回报blocked并结束本轮。DSH收到交付后独立验收。
后续启动由本原生定时计划处理。
```

## 三个队列工具的权限

原生权限确认可能使已经领取的任务等待。需要自动领取时，用户应明确允许本地队列的 claim_next、report_progress、report_delivery 自动执行，并在客户端原生工具确认设置中核对这三个工具。界面可能显示带 mcp_ 前缀的名称。已有文件与终端权限由各自原生设置管理。

首轮出现某个队列工具的权限确认时，展开“运行”旁的下拉菜单，为当前工具选择自动执行方式。分别核对三个队列工具的名称与所属连接器，具体选项文字以当前客户端为准。配置后再运行一次小任务，确认进度与交付都能自动回报。

工具权限在客户端中按实际显示的工具名称核对。安装更多连接器或升级客户端后，应重新检查对应关系。三个工具分别用于本地任务领取、续期与交付回报。它们对应的执行端实现见源码。[队列实现](../codearts_queue.py)

## 有限验收

先让 DSH 向项目测试子目录提交一个文件标记任务。等待一次真实定时触发，检查任务从 queued 进入 running，再进入 awaiting_review。原 DSH 应读取实际文件、检查内容并调用 review_delivery，最终状态为 accepted。

任务列表中的“立即执行”可以测试已经保存的计划内容。执行记录会区分定时和手动触发。每次新运行需要独立领取键，MCP 响应丢失重试时复用本轮键。原生权限请求或受阻应按实际情况处理。

## 用量与运行条件

每次定时领取可能发起模型请求，即使队列为空也可能消耗额度。按开发时段设置低频计划能够控制空闲开销。DSH 通知插件每两秒查询本地数据库，交付后的实际验收轮次使用 DSH 正常模型额度。

本机 MCP 和项目文件需要本机运行环境可用。电脑休眠、关机、客户端退出或本地连接失效时，自动执行需等待相应条件恢复。文件或终端权限确认仍可能要求用户处理。

需要暂停时，在官方“定时任务”任务列表停用相应计划。运行中的任务要结合其原生会话停止情况处理，DSH 的队列取消遵循现有协作取消流程。[任务状态与取消](usage.md)

## 2026-11-12 实测

Windows CodeArts 0.2.9 与 DSH 0.2.2-rc.1 中，通过官方创建表单保存工作区及 Cron，原生定时触发调用本地 MCP 领取 DSH 提交的测试任务。CodeArts 创建 17 字节 UTF-8 标记文件并回报交付，原 DSH 自动核对字节内容、写入验收记录，任务最终 accepted。初轮存在原生工具权限等待，后续核对了三个队列工具的自动执行设置。

第二轮使用原生“立即执行”启动保存后的计划。在三个队列工具自动执行设置下，CodeArts 自动领取另一个测试任务，回报进度、创建并核对 15 字节标记、提交交付，原 DSH 自动独立核对后记录 accepted。该轮验证了更新后的完整工作区范围和自动工具回报流程。

这些记录覆盖当前客户端的小任务运行。平台账号处置仍由实际使用和服务条款决定。[架构与账号风险](architecture-and-safety.md)
